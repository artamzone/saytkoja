# AGENTS.md

## Общие правила

- Работай только в текущем проекте.
- Перед изменениями сначала изучи структуру проекта.
- Не усложняй архитектуру без необходимости.
- Не добавляй backend, базу данных, авторизацию, корзину и оплату, если это не указано в TASK.md.
- Используй существующие зависимости, если они подходят.
- Не добавляй тяжелые UI-библиотеки без необходимости.
- Предпочитай простые и понятные решения.

## Стек проекта

- Vue 3
- Vite
- Vue Router
- Tailwind CSS v4
- lucide-vue-next

## Дизайн

- mobile-first
- адаптивность обязательна
- основной акцент на фотографии изделий
- минимальные анимации
- светлый премиальный стиль
- не генерировать изображения, если есть реальные фото

## Работа с фото

- Сначала просмотри все изображения в public/images.
- Используй реальные изображения из проекта.
- Не изменяй оригиналы без необходимости.
- Не создавай дубликаты изображений.
- Сохраняй соотношение сторон.
- Используй lazy loading.

## Код

- Используй Vue Composition API и <script setup>.
- Компоненты должны быть небольшими и понятными.
- Не дублируй код.
- Не создавай абстракции, если они используются один раз.
- Не используй Pinia без реальной необходимости.
- Не используй TypeScript, если проект уже на JavaScript.

## Проверка

После изменений обязательно:

1. npm run build
2. исправить ошибки сборки
3. проверить основные маршруты
4. проверить адаптивность:
   - 375 px
   - 768 px
   - 1440 px
5. проверить отсутствие горизонтального скролла

## Отчет

В конце кратко сообщи:

- что изменено
- какие файлы созданы
- что нужно заполнить вручную
- есть ли известные проблемы

## Глубина проверки

Для небольших визуальных правок выполняй только локальные проверки и сборку.
Для изменений маршрутов, структуры данных или логики проверяй затронутые страницы и соседние сценарии.
Не запускай избыточные проверки всего проекта без необходимости.

## Экономия контекста

- Для локальной задачи читай только связанные файлы.
- Не перечитывай весь проект без необходимости.
- Не пересказывай содержимое файлов в ответе.
- Не выводи полный код измененных файлов, если это не требуется.
- Используй diff и точечные изменения.
- Для визуальной правки не запускай проверки несвязанных модулей.
- Финальный отчет — максимум 5–7 строк.
