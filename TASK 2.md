# Задача

Упростить редактирование текущего Vue-сайта.

Не менять общий дизайн и не усложнять архитектуру.

Цель: чтобы основные данные сайта можно было редактировать в нескольких понятных файлах внутри `src/data/`, без изменения Vue-компонентов.

## Что нужно сделать

Создать или привести к единому виду:

src/data/
├─ site.js
├─ products.js
├─ categories.js
└─ content.js

## 1. site.js

Хранить здесь:

- название бренда
- телефон
- Telegram
- VK
- MAX
- адрес/город при необходимости
- ссылки соцсетей
- основные SEO-данные

Пример:

```js
export const siteConfig = {
  brandName: 'Название мастерской',
  phone: '+7 999 000-00-00',
  telegram: 'https://t.me/username',
  vk: 'https://vk.com/username',
  max: '',
  email: '',
  city: '',
  seo: {
    title: 'Сумки ручной работы',
    description: 'Сумки из натуральной кожи ручной работы'
  }
}
2. products.js
Все изделия должны редактироваться только здесь.
Для каждого изделия предусмотреть:
- id
- slug
- title
- category
- price
- shortDescription
- description
- material
- size
- colors
- images
- featured
- visible
Пример:
export const products = [
  {
    id: 1,
    slug: 'red-bag',
    title: 'Красная сумка',
    category: 'shoulder-bags',
    price: 'от 12 000 ₽',
    shortDescription: 'Компактная сумка ручной работы',
    description: 'Описание изделия',
    material: 'Натуральная кожа',
    size: '',
    colors: ['Красный'],
    images: [
      '/images/red-bag-1.jpg',
      '/images/red-bag-2.jpg'
    ],
    featured: true,
    visible: true
  }
]

Если visible: false, изделие не должно отображаться на сайте.
Если featured: true, изделие можно показывать в блоке популярных моделей на главной.
3. categories.js
Хранить категории отдельно.
Пример:
export const categories = [
  {
    id: 'classic',
    title: 'Классические сумки',
    subtitle: 'Вне времени',
    image: '/images/categories/classic.jpg',
    visible: true
  }
]

4. content.js
Вынести сюда все основные тексты страниц:
- hero главной
- блок о мастерской
- преимущества
- CTA
- доставка
- контакты
- заголовки разделов
Пример:
export const content = {
  hero: {
    title: 'Сумки ручной работы',
    text: 'Натуральная кожа. Продуманные детали.',
    buttonText: 'Смотреть коллекцию'
  },

  about: {
    title: 'Наша мастерская — ваши истории',
    text: ''
  },

  contactCta: {
    title: 'Не нашли подходящую модель?',
    text: 'Напишите мастеру — обсудим идею, цвет, размер и детали.',
    buttonText: 'Написать мастеру'
  }
}

5. Компоненты
Убрать из Vue-компонентов жестко прописанные:
- названия изделий
- цены
- контакты
- ссылки
- тексты главной
- категории
Компоненты должны получать данные из src/data/.
Не менять внешний вид без необходимости.
6. Фото
Все фотографии оставить в:
public/images/

Создать понятную структуру:
public/images/
├─ products/
├─ categories/
├─ hero/
├─ details/
└─ lifestyle/

Не дублировать существующие изображения без необходимости.
Если перенос файлов может сломать текущие пути, сначала обновить ссылки и проверить сайт.
7. Связь с мастером
Ссылки Telegram/VK/телефон должны браться только из site.js.
Сделать один helper для формирования ссылки на связь.
При открытии карточки изделия сообщение должно формироваться автоматически:
Здравствуйте! Мне понравилось изделие «Название изделия». Хотел(а) бы узнать подробнее.

Если контакт не заполнен, кнопка должна быть скрыта или disabled, а не вести на пустую ссылку.
8. README
Добавить короткий раздел:
Как редактировать сайт
Объяснить простыми словами:
- где поменять телефон
- где поменять Telegram/VK
- где изменить текст главной
- где добавить изделие
- как скрыть изделие
- где поменять цену
- как добавить фотографии
Без технической воды.
9. Ограничения
Не добавлять:
- backend
- CMS
- Directus
- PostgreSQL
- SQLite
- авторизацию
- админ-панель
- корзину
- оплату
- новые тяжелые зависимости
10. Проверка
После изменений:
1. Выполнить npm run build
2. Исправить ошибки
3. Проверить главную
4. Проверить каталог
5. Проверить хотя бы одну карточку изделия
6. Проверить 375px и 1440px
7. Убедиться, что визуально сайт не изменился без необходимости
В конце дать короткий отчет:
- какие data-файлы созданы
- какие компоненты переведены на них
- где теперь редактировать основные данные
- есть ли что-то, что осталось захардкожено
